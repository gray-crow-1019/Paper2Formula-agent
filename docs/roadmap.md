# 实施路线与验收

以下为开发计划与初始目标，不代表已经实现或已达到指标。

## 阶段 0：设计基线（当前）

完成组件边界、状态流程、数据模型、API/MCP 草案、示例输出和仓库文档。确认样本领域与模型部署方式后进入实现。

## 阶段 1：可追溯最小闭环

实现 PDF 上传、规范文档、Block/Anchor 存储、编号公式识别、Markdown/JSON/PDF 导出和 Web 报告跳转。先用人工标注及模型适配器的固定样本验证坐标，再接真实模型；所有演示明确区分真实识别和固定样例。

验收：选定文本型 PDF 可完整生成三类同版本成果；报告中的每条公式、定义、值能打开正确原文区域；错误、未知与来源缺失明确显示。

## 阶段 2：参数与复核闭环

加入分层检索、作用域绑定、单位/语法校验、人工暂停与恢复、修订审计和结果版本管理。接入持久化 Checkpointer、事务 Outbox、任务租约与幂等产物生成。

验收：Worker 重启、重复投递、模型超时、并发复核均不产生重复发布或丢失决定；确认/修改/保留未知可恢复并导出正确版本。

## 阶段 3：DOCX 与上线准备

加入 DOCX 隔离转换、旋转/裁剪坐标测试、文档权限、删除链路、资源限额、观测、备份恢复及依赖锁定。验证目标 PDF 阅读器中的批注显示与中文内容。

验收：Word 原文保持不变，报告明确使用转换 PDF 页码；两个用户之间任何 REST/MCP/Resource/下载路径都无法互访。

## 阶段 4：扩展能力

按评测结果考虑 OCR、复杂跨页公式、语义检索、多篇论文对照与专业量纲规则。只有检索基线存在明确瓶颈才引入 pgvector。

## 评测方案

初始建议准备至少 20 篇有权使用的文本型论文及 5 份 DOCX，覆盖中英文、双栏、符号表、重复符号和参数表格。按文档划分开发/校准/保留测试集，避免同一论文的页面分入不同集合。由人工标注公式区域、规范 LaTeX、定义关系、值/单位及来源；歧义由复核裁定并保留标注依据。

| 指标 | 初始验收目标 | 定义 |
|---|---|---|
| 编号公式召回率 | ≥ 90% | 找到的真公式 / 标注公式，报告精确率及漏检类型 |
| LaTeX 正确率 | ≥ 85% | 规范化后数学表达一致；单独报告完全匹配与人工语义判定 |
| 符号定义绑定准确率 | ≥ 90% | 自动确认定义中正确绑定比例，同时报告覆盖率 |
| 参数值/单位抽取 F1 | ≥ 90% | 对值、单位、实验条件和来源做联合匹配 |
| 抽样来源定位正确率 | 100% | 打开正确版本、正确页和对应原文区域 |
| 无证据事实混入最终报告 | 0 | 原文明示事实必须有有效证据；用户补充/推导单独标识 |
| 已知歧义的复核召回率 | ≥ 95% | 标注为不确定的项目中进入复核的比例 |
| 成果版本一致性 | 100% | Markdown/JSON/PDF 编号、锚点及 manifest 版本一致 |

这些阈值需在领域样本上评估后调整，不能当作模型效果承诺。每次变更解析器、模型、prompt 或检索策略都运行保留集回归，报告置信区间、复核率、耗时与费用；不能通过全部送人工来掩盖自动化质量。

## 关键集成验证

- DOCX 转换、PDF 旋转/裁剪、双栏和多行来源坐标。
- 同名不同义、下标差异、多个实验数值、未知单位与定义冲突。
- 进程崩溃发生在领域提交后/checkpoint 前，恢复仍幂等。
- 用户修订期间旧 Worker 完成，租约与 revision 防止旧版本覆盖。
- 三产物部分导出失败、下载链接过期、删除与正在执行的任务并发。
- 跨用户 task_id/doc_id/anchor/resource/object_key 访问均拒绝。
